# NOVA-SIM Project Overview

## 1. 프로젝트 개요

NOVA-SIM은 공간 안에서 사람, 시설, 조직, 차량 등의 객체가 각자의 상태와 규칙을 가지고 행동하며, 시간이 흐름에 따라 세계의 상태가 변화하는 공간 기반 시뮬레이션 프로젝트이다.

정해진 이벤트를 순서대로 실행하는 시뮬레이션이 아니라, 각 객체가 현재 상태와 주변 환경을 기반으로 행동하고 그 결과가 다시 다른 객체와 환경에 영향을 주는 구조를 목표로 한다.

장기적으로는 도시, 물류, 모빌리티, 로보틱스 등 실제 공간 문제를 실험할 수 있는 범용 시뮬레이션 환경으로 발전시키는 것을 목표로 한다.

---

## 2. 프로젝트를 시작한 이유

공간 데이터 분석을 처음 시작하면 가장 먼저 마주하는 문제는 공간 자체보다 **데이터의 복잡성과 불일치**이다.

같은 현실 세계의 객체를 표현하는 데이터라도 데이터를 구축하고 제공하는 기관에 따라 스키마, 속성, 표현 방식이 다르다. 갱신 주기 역시 동일하지 않기 때문에 같은 건물이나 도로를 나타내는 데이터 사이에서도 위치, 속성, 시점이 서로 일치하지 않는 경우가 발생한다.

분석 목적에 적합한 데이터를 결정하는 과정 역시 단순하지 않다.

어떤 문제를 해결할 것인지 정의하고, 필요한 공간 단위를 결정하고, 적절한 데이터를 탐색한 뒤, 서로 다른 출처의 데이터를 정제하고 연결해야 한다. 데이터의 정확도와 최신성까지 고려하면 실제 분석에 사용할 수 있는 데이터를 구축하는 것 자체가 하나의 프로젝트가 된다.

특히 개인이 실제 산업 환경과 유사한 데이터를 확보하는 데에는 한계가 있다.

물류, 모빌리티, 상권, 사람의 이동과 같은 분야에서는 기업 내부에서 생성되는 운영 데이터가 중요한 역할을 하지만 이러한 데이터는 외부에서 접근하기 어렵다. 공개 공간 데이터 역시 모든 분석 목적에 필요한 수준의 해상도, 시계열 정보, 속성을 제공하는 것은 아니다.

NOVA-SIM은 이러한 문제의식에서 시작했다.

> **실제 세계에서 원하는 데이터를 충분히 확보할 수 없다면, 통제 가능한 가상 세계를 만들고 그 안에서 데이터를 직접 생성해보자.**

NOVA-SIM에서는 공간 데이터를 이미 존재하는 정적인 분석 대상으로만 다루지 않는다.

World 안에서 사람, 차량, 시설 등의 객체가 존재하고 서로 상호작용하며, 시간이 흐름에 따라 상태가 변화하도록 만든다. 그리고 그 과정에서 발생하는 위치, 행동, 상태 변화와 사건을 데이터로 기록한다.

이를 통해 분석에 필요한 데이터를 직접 생성하고, 생성 과정과 조건을 알고 있는 데이터를 기반으로 다양한 공간 문제를 실험하고자 한다.

NOVA-SIM에서는 다음과 같은 질문을 다룰 수 있는 환경을 구축하는 것을 목표로 한다.

1. 특정 위치에 시설을 추가하면 사람과 차량의 움직임은 어떻게 달라지는가?
2. 물류센터의 위치와 처리 능력이 배송 시스템에 어떤 영향을 미치는가?
3. 도로, 건물, 시설과 같은 공간 환경이 Agent의 행동에 어떤 영향을 미치는가?
4. 여러 Agent의 개별 행동이 전체 시스템 수준에서 어떤 패턴을 만들어내는가?
5. 동일한 환경에서 공간 조건이나 Agent의 행동 규칙을 변경했을 때 결과는 어떻게 달라지는가?

NOVA-SIM의 목적은 단순히 가상의 데이터를 많이 생성하는 것이 아니다.

어떤 조건에서 데이터가 생성되었는지를 알고, 조건을 변경했을 때 결과가 어떻게 달라지는지를 추적할 수 있는 **재현 가능한 공간 시뮬레이션 환경**을 구축하는 것이 목표이다.

또한 NOVA-SIM의 개발 과정 자체를 Python, 데이터 모델링, 공간 데이터 처리, API, 데이터베이스, 시뮬레이션 등의 기술을 하나의 시스템 안에서 학습하고 연결하는 과정으로 활용한다. 장기적으로는 모빌리티, 물류, 도시 시뮬레이션과 로보틱스 분야까지 확장 가능성을 검토한다.

## 3. 핵심 목표

NOVA-SIM의 핵심 목표는 다음과 같다.

### 3.1 지속적으로 변화하는 World 구현

시뮬레이션에는 독립적인 시간이 존재하며, 시간이 진행됨에 따라 World와 World 내부 객체의 상태가 변경된다.

사용자가 모든 행동을 직접 지시하지 않아도 시뮬레이션이 자체 규칙에 따라 진행될 수 있어야 한다.

### 3.2 Agent 기반 행동 모델 구축

사람, 차량, 조직 등의 객체를 Agent로 표현하고 각각 다음 요소를 가질 수 있도록 한다.

* 현재 상태
* 위치
* 목표
* 행동 규칙
* 주변 환경에 대한 정보
* 다른 Agent와의 관계

초기에는 단순한 규칙 기반 행동부터 구현하고 이후 필요에 따라 복잡도를 높인다.

### 3.3 공간과 시뮬레이션의 결합

Agent의 행동은 공간과 독립적으로 이루어지지 않는다.

건물, 도로, 시설, 이동 거리, 접근성 등의 공간적 조건이 Agent의 행동과 시뮬레이션 결과에 영향을 줄 수 있도록 구성한다.

### 3.4 시뮬레이션 상태 기록

시뮬레이션 과정에서 발생하는 상태 변화를 데이터로 기록한다. 이를 통해 다음 작업이 가능하도록 한다.

* 시뮬레이션 재현
* 결과 비교
* 통계 분석
* 공간 분석
* 시각화
* 모델 검증

### 3.5 Observer 구축

World 내부 상태를 코드만으로 확인하지 않고 사용자가 관찰할 수 있는 인터페이스를 구축한다.

Observer는 World를 직접 변경하는 기능보다 다으 정보를 보여주는 것을 우선으로 한다.

* 현재 Simulation Time
* World 상태
* Agent 상태
* Agent 위치
* 주요 이벤트
* 시뮬레이션 진행 상태

## 4. 장기 방향

NOVA-SIM은 처음부터 거대한 디지털트윈 플랫폼을 만드는 것을 목표로 하지 않는다. 작은 시뮬레이션 엔진에서 시작하여 필요한 기능을 단계적으로 추가한다.

장기적으로 다음 영역과 연결할 수 있는 구조를 지향한다.

### 도시 시뮬레이션

* 사람 이동
* 시설 이용
* 교통 시설
* 도시 서비스 접근성

### 물류 시뮬레이션

* 물류센터
* 주문
* 배송 차량
* 배송 기사
* 배송 경로
* 처리 용량

### 모빌리티 시뮬레이션

* 차량 이동
* 경로 선택
* 교통 네트워크
* 수요 변화

### 보행자 및 군중 시뮬레이션

* 보행자 이동
* 목적지 선택
* 공간 밀도
* 혼잡 발생

### 로보틱스 및 자율주행

장기적으로 ROS2 및 로봇 시뮬레이션 환경과 연결하여 가상 환경에서 로봇 또는 자율주행 Agent를 실험할 수 있는 구조를 검토한다.

## 5. 핵심 구성 요소

현재 NOVA-SIM은 다음 개념을 중심으로 설계한다.

### World

시뮬레이션 전체 환경을 관리한다.

주요 책임은 다음과 같다.

* Simulation Time 관리
* Tick 관리
* World 상태 관리
* Agent 관리
* 시뮬레이션 진행

### Agent

World 내부에서 행동하는 객체이다.

* Person
* Vehicle
* Worker
* Robot

Agent는 자신의 상태와 환경에 따라 행동할 수 있다.

### Space

Agent와 객체가 존재하는 공간이다.

초기에는 단순한 좌표 또는 영역부터 시작하며, 이후 필요에 따라 실제 GIS 데이터 및 네트워크 구조로 확장한다.

### Simulation Time

현실 시간과 독립된 시뮬레이션 내부 시간이다.

Simulation Time을 기준으로 Agent의 행동과 환경 변화가 발생한다.

### Tick

World 상태를 한 단계 진행시키는 기본단위이다.

각 Tick에서는 필요한 상태 계산과 Agent 행동이 수행된다.

### Observer

시뮬레이션 상태를 사용자에게 보여주는 인터페이스이다.

Observer는 Simulation Engine과 분리하여 World 상태를 조회하고 표현하는 역할을 한다.

## 6. 개발 원칙

### 작은 단위부터 구현한다

처음부터 현실 전체를 모델링하지 않는다. 검증가능한 최소 단위의 World와 Agent부터 구현하고 기능을 단계적으로 확장한다.

### 재현가능한 시뮬레이션을 만든다

동일한 초기 조건과 동일한 Random seed를 사용했을 때 동일한 결괄르 재현할 수 있는 구조를 지향한다.

### 시뮬레이션과 표현 계층을 분리한다

Simulation Engine이 UI에 의존하지 않도록 구성한다.

Observer가 없어도 Simulation Engine은 독립적으로 실행될 수 있어야 한다.

### 상태를 데이터로 남긴다

화면에 보이는 결과만 만드는 것이 아니라 상태변화와 결과를 저장하고 분석할 수 있도록 한다.

### 기술보다 문제를 우선한다

새로운 기술을 사용하는 것 자체를 목표로 삼지 않는다.

PostGIS, Docker, React, ROS2 등의 기술은 NOVA-SIM에서 해결해야하는 문제가 명확해졌을 때 도입한다.

## 8. 현재 상태

현재 NOVA-SIM 프로젝트의 기본 Python 프로젝트 환경을 구성하고 있다.

## 9. 프로젝트의 성공 기준

NOVA-SIM의 성공 여부를 기능의 개수만으로 판단하지 않는다.

다음 조건을 만족하는 프로젝트를 목표로 한다.

1. 시뮬레이션 구조를 개발자가 직접 설명할 수 있다.
2. 동일한 조건에서 실험 결과를 재현할 수 있다.
3. Agent의 행동과 결과가 코드 수준에서 추적 가능하다.
4. 공간 데이터와 시뮬레이션 데이터를 함께 분석할 수 있다.
5. 새로운 Agent 또는 환경을 기존 구조를 크게 변경하지 않고 추가할 수 있다.
6. 시뮬레이션 결과를 데이터로 저장하고 검증할 수 있다.
7. 주요 기술 선택에 대한 이유와 한계를 문서로 설명할 수 있다.

---

## 10. 최종 지향점

NOVA-SIM의 최종 목표는 현실을 완벽하게 복제하는 것이 아니다.

현실의 특정 문제를 필요한 수준으로 추상화하고,

`공간 → Agent → 행동 → 시간 → 상태 변화 → 결과분석`

이라는 과정을 하나의 시스템 안에서 구현할 수 있는 시뮬레이션 환경을 만드는 것이 목표이다.

**NOVA-SIM은 이러한 환경을 직접 설계하고 발전시키는 장기 프로젝트이다.**
